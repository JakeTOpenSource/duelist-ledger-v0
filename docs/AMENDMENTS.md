### A4.2 Normative text

**A4.2.1 Agent link (new §3.8; §2; §12).** The gateway accepts a session's messages only over the transport it bound at SESSION_OPEN: the pipe of the agent process it spawned, the connection it accepted for that session, or, in the harness, the direct call from the agent object it was given. At SESSION_OPEN it generates a 32-byte session key with `secrets.token_bytes(32)`, hands it to the agent once over that transport, and logs `H(session_key)` in the SESSION_OPEN body. Every agent message carries `"mac"`, the HMAC-SHA256 under the session key of the canonical message without the mac. A message whose mac does not verify, or that arrives over another transport, is logged as LINK_REJECT (actor gateway, scope L2:agent->gate, body `{reason}`), and nothing else happens: no decide(), no state change, no HOLD, no case, no strike, no probe, and the clock does not advance. The sender receives LINK_REJECT. The check is on in every mode, pass-through included; it is a pipeline-integrity sensor, not a judgment of the proposal. The seq rules of §3.7 apply after the mac verifies. §2 now names three keys per run: the gate key, the witness key, and one session key per session. Fault hook (§8): `forge_message{session?, after_seq}`: right after the proposal with seq `after_seq` of session index `session` (0-based, default 0) is answered, the harness injects one copy of it with seq `after_seq + 1` and a mac computed under a random key. Its signal is LINK_REJECT.

**A4.2.2 Effect token (§4, replacing "Action token"; §0; §2; §5; §8; §9).** On ALLOW or ESCROW the gateway mints `{tool, args_hash, decl_step, envelope_commit, policy_hash, audience, nonce, expires_t}` and signs the canonical token with its Ed25519 signing key. `args_hash` is `H` of the args with guarded values in clear and content values as digests. `audience` is the receiver's id: `world:<house_id>` in the single-house harness, the receiving house's id in the cross-house interface (§19). `expires_t` is unchanged (mint time plus twice the largest escrow window). The **receiver** verifies before applying anything: the signature under the gateway's verify key, which is published in the SESSION_OPEN body and the run manifest; `audience` equals its own id; `envelope_commit` equals the agreement it holds for this agent and session, which in the single house is the SESSION_OPEN's envelope commit; `policy_hash` equals the one it holds; the nonce is unused, so the receiver keeps every nonce it has applied; `expires_t` is later than its clock; and `args_hash` equals the hash of the args it is asked to apply. On any failure the receiver applies nothing and writes a refusal receipt `{rcpt_seq, prev, sink_class, args_digest, effect_id, refused}` with `refused` one of ARGS, SIGNATURE, AUDIENCE, ENVELOPE, POLICY, NONCE, EXPIRED. At VERIFY the gateway reads the refusal: ARGS is T4_ARGS_MISMATCH (TRIP at L1, a session trip, as before); every other code is T5_TOKEN_REFUSED: TRIP on L2 gate->world:\<sink_class\>, ALARM GATE_FAULT at L3, case sensor-fault, the item DISCARDed, the session continuing, exactly as T3 is handled. For reconcile (§9) a refusal receipt is neither a bypass nor a gap. §0 admits one optional package for Ed25519, `cryptography` or `pynacl`; when it is absent the gateway signs tokens with HMAC under the gate key, the receiver verifies the same way, and the report's caveat line says "signatures are HMAC stand-ins". A claim that no effect happens without proof requires the real signatures. Fault hook (§8): `forge_token{index, field}` with `field` one of `audience`, `envelope`, `nonce_reuse`, `expiry`, `signature`: before release of the k-th escrowed item the harness alters that field of its token; `nonce_reuse` replaces the nonce with that of the most recently released item of the same sink class and never fires if there is none. Its signal is T5. `mutate_escrow` is unchanged and its signal stays T4.

**A4.2.3 Typed slots (§3.3, §3.4, §4 T1 row).** The sink table gains a `type` per slot: `read_file.path` path; `fetch_web.url` url; `read_memory.key` key; `write_workspace.path` path, `content` text; `send_email.to` address, `body` text, `attach` path; `pay.payee` payee, `amount` amount, `memo` text; `persist_memory.key` key, `content` text; `schedule.action` action, `target` address. T1_HOUSE now reads: any path-typed argument value starts with a house_prefixes entry; text-typed values are never scanned by T1. `dest_class` applies to address-typed and payee-typed values; `{"max": m}` applies to amount-typed slots only; path-typed pinned values compare as strings.

**A4.2.4 TRIP and CONTAIN (§5.2 rewritten; §3.4; §5; §5.5; §5.6; §14).** A TRIP outcome is handled one of two ways, fixed at the moment of the trip by its case class (§5.6):
- **Session TRIP,** when the case is agent-violation (T1 or T2 while the session is untainted), and always for T4. As before: revoke all tokens, DISCARD every escrow item of the session with no refund, relabel QUARANTINED every world artifact the session wrote while tainted, with a QUARANTINE entry each, set the session scope to TRIP, end the session with outcome TRIP. No automatic resume, ever.
- **CONTAIN,** when the case is injection-suspected (T1 or T2 with `failing_tainted` true, or while `session_tainted`). Then:
  1. The TRIP entry is logged at scope **L0:\<item\>** with `contained: true`, the item scope goes to TRIP and nothing leaves it, and a CONTAIN entry follows. The proposal executes nothing: no token, no debit, no receipt. The agent receives DENIED:CONTAINED and continues with its next op.
  2. The case's cited origins (the failing argument's label origins, or the session context's origins when T1/T2 has no failing argument, as §5.6 already defines for common-mode) are added to the session's **quarantine set**. A case that cites no origin adds every origin in the session's context label.
  3. Every stored value of the session whose label cites a quarantined origin is relabeled QUARANTINED (integrity -1). The session context label's integrity becomes -1. Every world artifact the session wrote whose label cites a quarantined origin is relabeled QUARANTINED, with a QUARANTINE entry each.
  4. Escrow items of the session whose guarded-slot labels or attached-file labels cite a quarantined origin are DISCARDed with no refund. Other items stay staged and follow the normal release rules.
  5. Later proposals are decided by the ordinary rules over the new labels. A literal argument now carries integrity -1, so a free guarded value is tainted (H4, hard-denied by §4 unless the step is attended or the slot derived); a pinned value still passes H3 when it is in the pinned list; T2 and H8 apply to content as always.
  6. A CONTAIN adds no strike and no probe. Its case is injection-suspected and feeds common-mode as before.
  7. The session's contain counter adds 1. When it reaches `contain_limit` (policy, default 3), a HOLD with reason CONTAIN_LIMIT (L1) is logged and the session closes with outcome CLOSED; its remaining escrow items are discarded with no new HOLD.
  8. A session in which at least one CONTAIN occurred and which neither closed nor tripped ends with outcome **CONTAINED**, with SESSION_CLOSE and anchor as usual.

**A4.2.5 Hard deny and the declaration-time allowlist (§3.5, §3.6, §4, §5.1, §5.5, §5.6, §6, §12, §14).** Rule order, after the T-rules and before the HOLD sentence: if the reasons include H3 or H4 with `failing_tainted` true and the proposal's step is not attended, the outcome is DENY with no resolver, its primary per the mixed-reason rule (§5.1). This was mode A7's rule in v0.2; it is now the default in every gated mode. A declaration step gains two optional fields. `"attended": true` (default false) makes a tainted H3/H4 on that step a HOLD resolved by repin only; approve_once is never available for a tainted H3 or H4. `"derived": {"<slot>": {"sender_of": "<step_id>"}}` binds a guarded address-typed slot to a rule instead of a value: the proposal's value passes when it equals the `sender` recorded by the world for at least one value that a call of the named read step (a declared `read_inbox` or `fetch_web` step) delivered to this session; otherwise the reason is H3_PINNED_MISMATCH, with `failing_tainted` from the argument as usual. Each guarded slot of a step appears in exactly one of `pinned`, `free_guarded` and `derived`; anything else is a SCHEMA reject. Envelope check (e): a derived slot requires `"derived:sender_of"` in `destinations[tool.slot]`, else H0_ENVELOPE. §5.1: repin is available for H8, and for H3 or H4 on an attended step; approve_once is unavailable for a tainted H3 or H4 in every case. §6: the rubber stamp repins only where a HOLD offers repin. §5.5: every no-resolver DENY counts under the per-tool rule unless its primary is S0 or H5_*. §5.6: every HOLD, no-resolver DENY, TRIP and H0 opens one CASE. §12: A7 is redefined as **attended**: every step is treated as `attended: true`, so a tainted H3/H4 holds for repin instead of being denied; this is the v0.2 default behavior kept as an ablation. §14: `denies` lists the primary codes of no-resolver DENYs in any mode.

**A4.2.6 PAUSE, human RUN-to-HOLD (§5, §5.1, §5.6, §10, §14; deferred).** The principal may put any L0 item or L1 session of their house into HOLD, and the operator any L2 link or L3:org, by a PAUSE: a HOLD entry with reason PAUSE, actor principal or operator, at that scope, applied with source H. Proposals already decided ALLOW and executing complete. Escrow items in a paused scope are not released while it is held: the release re-check finds the scope not RUN and logs S0_SCOPE_HELD on the item, re-checked at every pass, as §5 already says. While an L1 or L3 PAUSE is in force, every agent message of an affected session is logged as sent (PROPOSE, AMEND, CHALLENGE, NARRATE or FINISH) with `paused: true`, is not decided, receives HELD, and does not advance the clock. The same actor lifts the PAUSE with a RESOLVE (HOLD->RUN, source H). A PAUSE adds no strike and no probe; its case class is none. §10: H may also do RUN->HOLD. **Deferred:** no v0.3 build must implement PAUSE; the v0.x scripted principal and operator never pause; the fault hook `pause{scope, after_t, held_messages}`, scenario X13 and the §17 test are listed as deferred, and a build that omits PAUSE declares it as a known nonconformance under the protocol.

**A4.2.7 Known residual: attacker-triggered restriction (§18).** An attacker who can deliver content to the agent can force contained attempts, up to `contain_limit` per session, after which the session closes, and can, across `common_mode_sessions` sessions citing one origin, raise the org-wide COMMON_MODE hold on R2/R3 actions. Both cost availability and never integrity, and both are the intended response to a wave. Text-triggered T1 trips are removed by typed slots; T2 needs a house canary token, which an attacker does not hold. Compute exhaustion by floods of proposals is bounded by the READ_EXTERNAL fuse and by `contain_limit`; no other sink class has a rate fuse in v0.x, and that is recorded as a residual.

**A4.2.8 Foreign labels and the cross-house interface (§3.1; new §19).** Labels are house-local. A value that crosses a house boundary carries weight only if its label is signed by the issuing house's gateway (Ed25519 over the canonical pair of value digest and label) and the receiving house holds that gateway's verify key from the handshake; an unsigned or unverifiable foreign label is dropped, and the value enters as UNTRUSTED (integrity 0) with origin `house:<sender id>` and that id as `sender`. A receiving house never relaxes its own rules on a foreign label: its own envelope and flow rules apply to every effect that arrives. §19, specified now and exercised by the two-house run rather than by the v0.x suite: the parties are house A's gateway, house B's receiver, and a witness W with its own key, file and process. At the handshake, A and B exchange and each log `envelope_commit` (the agreed envelope for A's agent at B), each side's `policy_hash`, and verify keys, and both send heads to W. Every effect from A at B carries a token with audience B (A4.2.2); B keeps its own receipt chain and sends its heads to W. B may recompute any AUTHORIZE entry of A's diary from its logged inputs and A's published policy hash; a mismatch is B's ALARM REPLAY_MISMATCH at its L3, after which B refuses further tokens from that session. B verifies A's diary against W's heads on request. Tests for the two-house run: T2H-1, the handshake commit predates the agent's first untrusted read; T2H-2, B recomputes 100% of A's decisions; T2H-3, effects without tokens, with reused nonces, with the wrong audience or envelope, or with altered args are refused by B with refusal receipts and never applied; T2H-4, a tampered A diary is detected by B through W, and a tampered W is detected by A and B through cross-check; T2H-5, an unsigned foreign label arriving at B enters as UNTRUSTED.

### A4.6 Required tests added (§17)

- A message with a bad MAC, or over another transport, leaves only a LINK_REJECT entry: no decision, no state change, no case, no probe, no clock tick; a valid MAC with a repeated seq is a SEQ_GAP.
- A token with a wrong audience, wrong envelope commit, wrong policy hash, reused nonce, expired time, or bad signature is refused by the receiver with the matching refusal code and nothing is applied; an altered argument is T4; each other refusal is T5 on L2 with an alarm.
- T1 never trips on a text-typed value; a path-typed value with a house prefix trips.
- A tainted T2 trips the item at L0 and the session continues; quarantined origins relabel stored values and artifacts; an escrow item carrying a quarantined origin in a guarded or attached slot is discarded and one that does not is released; the k-th containment closes the session; an untainted T2 is a session trip.
- In V2 a tainted H4 on an unattended step is a no-resolver DENY; on an attended step it is a HOLD with repin only; a derived slot passes only when the value equals the named read step's recorded sender, and otherwise is H3.
- Deferred: PAUSE.
- Two-house, run separately: T2H-1 to T2H-5 (A4.2.8).
