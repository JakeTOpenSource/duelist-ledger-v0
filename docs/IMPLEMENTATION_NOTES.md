# Implementation notes (Track B, contract v0.3)

This build targets **contract v0.3**: `BUILD_SPEC.md` at tag `contract-v0.3`, commit `431a14a360371479e77658cbf9d6adcd7315d104` (sha256 `e48af7c6…eff8eed77`), with `TRACK_SEPARATION_PROTOCOL.md` (sha256 `c4d4f90c…9c539ff71`). It brings the published v0.1 build (repo commit `64e33e5`, written blind on Opus 5.5 from contract v0.1) into conformance with v0.3, which is v0.1 plus amendments A3 (v0.2, no build was made) and A4 (v0.3). This update was written blind on Claude Fable 5.1 (`claude-fable-5-1`, Anthropic), the same family as Track A. No Ed25519 package was available in the build environment, so effect tokens are signed with the HMAC-SHA256 stand-in of sec. 2/4 and the caveat line says so.

Part 1 lists every reading the v0 build recorded, with its status under v0.1 (as recorded then) and now under v0.3. Part 2 lists the ambiguities the v0.1 build hit, with their status under v0.3. Part 3 lists the **new** ambiguities this build hit under v0.3, each with the reading chosen.

Status vocabulary:

- **kept**: the contract is still silent, and the reading is unchanged.
- **pinned by v0.3**: v0.3's text now fixes the point, and the build matches that text.
- **changed by v0.3**: v0.3's text differs from the earlier reading. The entry says what changed.

## Part 3: new ambiguities hit under v0.3

v0.3 aims for zero, so each is listed with the clause and the reading chosen. Where a careful reader could take the other side, the alternative is named.

| # | spec section | ambiguity | reading chosen |
|---|---|---|---|
| V1 | 3.3, 4 | **T1 on an undeclared proposal.** Sec. 4 says the four rules include "T1 over every literal argument value"; sec. 3.3 says T1 scans path-typed values only and never text. An unknown tool has no slot types. | With a known tool (an unresolvable handle elsewhere), T1 scans the **path-typed literal** values only, as sec. 3.3 requires.
